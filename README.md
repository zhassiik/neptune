# Neptune UBT | Жазира Тұрғымбай — ҰБТ математикасына дайындық платформасы

Оқушылар мұғалім дайындаған 40 сұрақтық ҰБТ нұсқаларын онлайн орындайды. Жүйе жауаптарды серверде тексеріп, ҰБТ бағалау ережесі бойынша (максимум 50 балл) нәтижені есептейді.

**Технологиялар:** Next.js 15 (App Router) · TypeScript · Tailwind CSS 4 · Supabase (Auth, PostgreSQL, Storage) · Zod · Vitest

## Жылдам іске қосу

Талап: **Node.js 20+** және [Supabase](https://supabase.com) аккаунты (тегін жоспар жеткілікті).

```bash
npm install
cp .env.example .env.local      # кілттерді толтырыңыз (төменде қараңыз)
npm run dev                      # http://localhost:3000
```

Толық тізбек:

1. Supabase жобасын құрып, migration-ды іске қосыңыз ([төменде](#supabase-ты-баптау)).
2. `.env.local` файлын толтырыңыз.
3. `npm run dev` → сайтта **Тіркелу** арқылы мұғалім аккаунтын ашыңыз.
4. Сол аккаунтты әкімші етіңіз: `npm run make-admin -- teacher@mail.kz`
5. Админ-панель → **Жаңа нұсқа қосу** → курсты («ТАҢҒЫ 200 НҰСҚА ТАЛДАУ») таңдап, 40 скринді жүктеп, дұрыс жауаптарды белгілеңіз ([толығырақ](#нұсқа-қосу-скрин--жауап-кілті)).
6. Басқа браузерде (немесе инкогнитода) оқушы ретінде тіркеліп, тестті тапсырып көріңіз.

## Supabase-ты баптау

### 1. Жоба құру

[supabase.com/dashboard](https://supabase.com/dashboard) → **New project**. Аймақ ретінде жақын орналасқан серверді таңдаңыз (мысалы, Frankfurt).

### 2. Database migration

**A нұсқасы — SQL Editor (ең оңай):**
Dashboard → **SQL Editor** → **New query** → `supabase/migrations/` ішіндегі файлдарды **ретімен** іске қосыңыз:

1. `20261025000001_init.sql` — негізгі кестелер, RLS, сұрақ суреттері
2. `20261026000001_courses_and_videos.sql` — курстар (3 бастапқы курс), видео-талдау, курс мұқабалары
3. `20261027000001_branding_covers.sql` — платформа атауы (Neptune UBT | Жазира Тұрғымбай) және үш курстың мұқабалары (`public/covers/`)
4. `20261028000001_cloudflare_stream_access.sql` — Cloudflare Stream видеолары (`video_provider`, `cloudflare_video_uid`, `video_status`) және курсқа рұқсат (`courses.access_mode`, `course_enrollments`)
5. `20261029000001_device_control.sql` — құрылғы бақылауы (`user_devices`, `revoked_sessions`, `login_attempts`), сессияға байланған RLS, rate limit

**B нұсқасы — Supabase CLI:**

```bash
npx supabase login
npx supabase link --project-ref <project-ref>
npx supabase db push
```

> **`type "user_role" already exists` қатесі шықса** — migration бұрын (толық немесе жартылай) орындалған. Алдымен тексеріңіз:
>
> ```sql
> select count(*) from information_schema.tables
> where table_schema = 'public'
>   and table_name in ('profiles','platform_settings','test_variants','questions','answer_options',
>                      'matching_options','matching_items','test_attempts','student_answers','attempt_scores');
> ```
>
> Нәтиже **10** болса — migration толық орындалған, қайта іске қосудың қажеті жоқ. Одан аз болса — SQL Editor-да [`supabase/reset.sql`](supabase/reset.sql) іске қосыңыз (migration құрған кестелерді өшіреді, Auth пайдаланушылары сақталады), содан кейін migration-ды қайта іске қосыңыз.

Migration мыналарды құрады: 9 негізгі кесте (+ `platform_settings`), индекстер, триггерлер, RLS саясаттары, `question-images` жабық Storage bucket-і (5 МБ, JPG/PNG/WebP) және оның access policy-лері.

### 3. Кілттер (`.env.local`)

Dashboard → **Project Settings → API**:

| Айнымалы | Қайдан алу |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `anon` `public` кілті |
| `SUPABASE_SERVICE_ROLE_KEY` | `service_role` кілті — **тек серверде**, ешқашан клиентке бермеңіз |
| `NEXT_PUBLIC_SITE_URL` | Сайт адресі (локалда `http://localhost:3000`) |

### 4. Authentication баптаулары

Dashboard → **Authentication → URL Configuration**:

- **Site URL:** `http://localhost:3000` (production-да — нақты домен)
- **Redirect URLs:** `http://localhost:3000/auth/callback` (және production домені: `https://<домен>/auth/callback`)

Email растау: **Authentication → Providers → Email → Confirm email**. Қосулы болса, оқушы тіркелгеннен кейін поштадағы сілтемені басуы керек. Локалда тез тексеру үшін оны уақытша өшіруге болады.

> Қазақша email хаттары үшін: **Authentication → Email Templates** бөлімінде шаблон мәтінін аударыңыз.

### 5. Әкімші (мұғалім) тағайындау

Сайтта тіркелгеннен кейін:

```bash
npm run make-admin -- teacher@mail.kz
```

немесе SQL Editor арқылы:

```sql
update public.profiles set role = 'admin' where email = 'teacher@mail.kz';
```

Кейін әкімші админ-панельдегі **Оқушылар** бетінен басқа пайдаланушыларға да әкімші құқығын бере алады.

## Нұсқа қосу: скрин + жауап кілті

1. **Админ-панель → Жаңа нұсқа қосу**: курс, нөмір (1, 2, 3…), атауы (мысалы, «Контекст Қарағай ағашы»), қаласаңыз видео-талдау сілтемесі мен ұзақтығы. Оқушыға «НҰСҚА 1. Контекст Қарағай ағашы» → «НҰСҚА №1» (тест) + «ТАЛДАУ №1» (видео) болып көрінеді.
2. **Жылдам енгізу** беті автоматты ашылады:
   - **1-қадам** — 40 скринді бірден таңдаңыз немесе сүйреп әкеліңіз. Файлдар атауы бойынша ретке келтіріледі (`1.png`, `2.png` … `40.png`) және 1–40 сұрақтарға кезекпен беріледі. Үлкен суреттер автоматты кішірейтіледі.
   - **2-қадам** — әр сұрақтың дұрыс әрпін басыңыз (бірден сақталады): 1–30 бір әріп, 31–35 A және B үшін нөмір, 36–40 бір–үш әріп. Нұсқа саны (4/5, 5/6) скриндегімен бірдей болуы керек.
3. **Preview** арқылы тексеріп, **Жариялау** батырмасын басыңыз (40 сұрақтың бәрі дайын болуы керек).

Жауап мәтіндерін жазу міндетті емес: олар скринде болса, оқушы тек A/B/C/D… әріптерін таңдайды. Мәтін немесе түсіндірме қосу керек болса — «Толық редактор».

**Видео-талдау:** YouTube (жасырын/unlisted сілтеме), Vimeo, Kinescope немесе тікелей `.mp4` сілтемесі қолданылады. Видео тек жүйеге кірген оқушыларға көрінеді. Ескерту: YouTube unlisted сілтемесін білетін кез келген адам ашып көре алады — ақылы курс үшін Kinescope немесе Vimeo (домен бойынша шектеу) сенімдірек.

**Курстар:** Админ-панель → **Курстар** — мұқаба, атауы, бағасы, күйі (Ашық / Жақында / Жоба). Баға тек көрсету үшін — төлем жүйесі әзірге жоқ.

## Cloudflare Stream: қорғалған видео-талдаулар

Видео сайттың ішінде, өз плеерімізде (hls.js) ойнатылады:
- сапа интернет жылдамдығына қарай автоматты бейімделеді, қолмен Auto / 360p / 480p / 720p / 1080p таңдауға болады;
- жылдамдық 0.75×–2× аралығында;
- жүктеп алу батырмасы жоқ, оң жақ мәзір бұғатталған;
- оқушының аты мен email-і watermark ретінде 20–30 секунд сайын орнын ауыстырады.

**Қорғау тізбегі:** Cloudflare-да видео `requireSignedURLs: true` + `allowedOrigins`. Плеер `POST /api/video/<variantId>/token` арқылы signed URL сұрайды. Сервер:
1. Supabase арқылы пайдаланушыны тексереді (кірмеген болса — 401).
2. Video UID-ді **клиенттен емес**, Supabase-тегі сабақтан алады.
3. Курсқа рұқсатты тексереді (рұқсат жоқ болса — 403).
4. Signing key-мен 1 сағаттық RS256 token жасайды.

Cloudflare кілттері ешқашан браузерге жіберілмейді. Token мерзімі бітер алдында плеер оны өзі жаңартады, сондықтан 1 сағаттан ұзақ видео тоқтамайды.

**Watermark және толық экран:** Cloudflare iframe ішіндегі толық экранда сайттың watermark-ы көрінбейді. Сондықтан iframe емес, HLS плеер қолданылады. Толық экранға видео мен watermark бар контейнер шығады. iPhone Safari бетті толық экранға шығаруға рұқсат бермейді, сондықтан онда плеер бет үстіне толық экран режимінде ашылады — watermark көрінеді.

**Курсқа рұқсат:** Админ-панель → Курстар → курс → «Кімге ашық»:
- **Барлық тіркелген оқушыларға** — бұрынғыдай.
- **Тек рұқсат берілген оқушыларға** — сол беттегі тізімге оқушыны email арқылы қосасыз. Рұқсат курстың тесттеріне де, видеоларына да әсер етеді.

### Баптау қадамдары

1. **Cloudflare Dashboard → Stream:** видеоны **Upload** арқылы жүктеңіз. Видеоны ашып, **Video ID**-ді (32 таңба) көшіріңіз — бұл Video UID.
2. **Account ID:** Dashboard-тың оң жағында (немесе Stream бетінде).
3. **API Token:** My Profile → API Tokens → Create Token → Custom → рұқсат: *Account → Stream → Edit*.
4. **Customer code:** Stream → видео → *Embed* қойындысындағы `https://customer-XXXX.cloudflarestream.com` → `XXXX` бөлігі.
5. `.env.local`-ға 1–4-қадамдардағы мәндерді жазып, signing key жасаңыз (оны Dashboard-та жасау мүмкін емес, тек API арқылы):
   ```bash
   npm run cf:signing-key
   ```
   Шыққан екі жолды (`CLOUDFLARE_STREAM_SIGNING_KEY_ID`, `CLOUDFLARE_STREAM_SIGNING_PRIVATE_KEY`) `.env.local`-ға қойып, серверді қайта іске қосыңыз.
6. **Админ-панель → Нұсқалар → нұсқа → Нұсқа баптаулары → Видео-талдау → «Cloudflare Stream (қорғалған)»** → Video UID → Сақтау.
7. Сол беттегі **«Видео-талдау: Cloudflare Stream»** панелінде **«Қорғауды орнату»** батырмасын басыңыз. Ол `requireSignedURLs` пен `allowedOrigins`-ті орнатады: production домені (`NEXT_PUBLIC_APP_URL`), development кезінде `localhost:3000` және `CLOUDFLARE_STREAM_EXTRA_ORIGINS`. Содан кейін «Preview» арқылы тексеріңіз.

## Құрылғы бақылауы (аккаунтты таратудан қорғау)

- Бір аккаунтқа ең көбі **4 белсенді құрылғы** кіре алады. Лимитті **Админ-панель → Баптаулар** бөлімінде немесе `MAX_DEVICES_PER_USER` env айнымалысымен өзгертесіз (env басым). Әкімшілерге лимит қолданылмайды.
- **Құрылғы** — `nep_did` httpOnly cookie-дегі кездейсоқ UUID. Бетті жаңарту немесе сол браузерден қайта кіру жаңа құрылғы саналмайды. Инкогнито режимі, басқа браузер немесе cookie тазалау жаңа құрылғы болып есептеледі.
- **Тіркеу.** Әр сәтті кіруде құрылғы `register_device()` PostgreSQL функциясымен **atomic** тіркеледі (пайдаланушы бойынша advisory lock). Лимит толса, сессия бірден жабылып, «Бұл аккаунтта рұқсат етілген құрылғылар саны толды…» деген хабарлама шығады.
- **Үш деңгейлі қорғау:**
  1. **RLS:** `is_session_authorized()` JWT ішіндегі `session_id`-ді `user_devices`-пен салыстырады. Тіркелмеген, өшірілген немесе бұғатталған сессия талпыныстарды, жауаптарды, нәтижелерді және курс рұқсаттарын Supabase-тен тікелей сұрағанда да көрмейді.
  2. **Сервер:** `getCurrentUser()` әр сұраныста құрылғыны тексереді. Беттер, API (`/api/attempts`, `/api/video`), server action-дар осы арқылы өтеді.
  3. **Middleware және heartbeat:** ашық тұрған бет минут сайын тексеріледі. Құрылғы өшірілсе, бет 1–2 минут ішінде кіру бетіне жіберіледі.
- **Құрылғыны шығару.** Сессия `revoked_sessions`-қа жазылып, `auth.sessions`-тан өшіріледі (refresh token жойылады). Supabase сессия жолын өшіруге рұқсат бермесе де, RLS пен сервер ол сессияны бірден бұғаттайды. Access token мерзімі бітсе де (≤ 1 сағ), ол қайта тіркеле алмайды.
- **Оқушы:** «Менің нәтижелерім» → **Менің құрылғыларым** (`/cabinet/devices`): құрылғыдан шығару, басқа барлық құрылғылардан шығу.
- **Әкімші:** Оқушылар → **Құрылғылар** (`/admin/students/<id>`): құрылғыны өшіру, барлық сессияны тоқтату, аккаунтты бұғаттау.
- **Кіру шектеуі (rate limit):** email бойынша 15 минутта 5, IP бойынша 30 сәтсіз әрекет.
- **Optional:** Turnstile CAPTCHA (3 сәтсіз әрекеттен кейін) және жаңа құрылғы туралы email (Resend). Олар `.env`-те кілттер берілгенде ғана қосылады.

### Database кестелері

| Кесте | Мақсаты |
| --- | --- |

## Бағалау ережелері

Модуль: [`src/lib/scoring/index.ts`](src/lib/scoring/index.ts), тесттер: [`scoring.test.ts`](src/lib/scoring/scoring.test.ts).

| Сұрақтар | Тип | Балл |
| --- | --- | --- |
| 1–30 | Бір дұрыс жауап (radio) | дұрыс — 1, әйтпесе — 0 |
| 31–35 | Сәйкестендіру (A, B → dropdown) | екеуі дұрыс — 2, біреуі — 1, әйтпесе — 0 |
| 36–40 | Бірнеше дұрыс жауап (checkbox, макс. 3 таңдау) | төмендегі кесте |

Бірнеше дұрыс жауабы бар сұрақтар (дұрыс жауаптар саны 1–3, максимум 2 балл). Екі сан бөлек есептеледі:
**белгіленбей қалған дұрыс жауаптар** және **артық белгіленген қате жауаптар**. Қателік саны — осы екеуінің **үлкені** (қосылмайды):

| Қателік саны | Балл | Мысалдар (дұрыс → белгіленген) |
| --- | --- | --- |
| 0 | 2 | A → A · AB → AB · ABC → ABC |
| 1 | 1 | A → AB · AB → A · ABC → AB · ABC → ABE (C орнына E) |
| 2+ | 0 | A → ABC · AB → ADE · ABC → A · ABC → ADE |

Ештеңе белгіленбесе немесе бірде-бір дұрыс жауап белгіленбесе (мысалы, A → B) — **0 балл**.

Барлығы: 30 + 10 + 10 = **50 балл**.

> Ереже [`scoreMultiple`](src/lib/scoring/index.ts) ішінде және оның тесттерінде бекітілген. Оқушы 3-тен көп нұсқа таңдай алмайды (UI бұғаттайды, сервер де тексереді).

## Қауіпсіздік моделі

- **Row Level Security** барлық кестелерде қосулы.
- **Дұрыс жауаптар клиентке берілмейді:** `questions`, `answer_options`, `matching_items`, `matching_options` кестелеріне тікелей SELECT тек әкімшіге рұқсат. Оқушыға сұрақтар сервер арқылы `toPublicQuestion()` тазалағаннан кейін (`is_correct`, `correct_option_id`, `explanation` жоқ) беріледі.
- **Балл тек серверде есептеледі:** `/api/attempts/[id]/submit` service-role арқылы дұрыс жауаптарды оқып, `scoreAttempt()` орындайды да, нәтижені `finalize_attempt()` SQL функциясы арқылы атомарлы жазады. Бұл функцияны тек `service_role` шақыра алады.
- **Оқушы басқалардың нәтижесін көрмейді:** `test_attempts`, `student_answers`, `attempt_scores` — тек өзінікі (`student_id = auth.uid()`).
- **Жарияланбаған нұсқалар жасырын:** `test_variants` — оқушыға тек `status = 'published'`.
- **Жауапты өзгерту:** тек өз талпынысына, тек `in_progress` күйінде және мерзім өтпей тұрып (`can_write_answer()`). Тест аяқталғаннан кейін жауаптарды өзгерту мүмкін емес.
- **Рөлді өзгертуден қорғау:** триггер оқушыға өз рөлін `admin`-ге ауыстыруға жол бермейді.
- **Storage:** `question-images` bucket-і жабық. Жүктеу/өшіру — тек әкімші. Оқушыға суреттер 6 сағаттық signed URL арқылы ғана беріледі.
- **Валидация:** барлық формалар мен API сұраныстары Zod арқылы серверде тексеріледі; ашық redirect-тен қорғау бар.

## Негізгі мүмкіндіктер

**Оқушы:** тіркелу/кіру · курс блоктары (мұқаба, баға) · курс беті: «НҰСҚА N» бөлімдері → тест + видео-талдау · бастау / жалғастыру / қайта тапсыру · бір сұрақ бір экранда · 1–40 навигация (көк — жауап берілген, қою көк жиек — ағымдағы, сұр — жауапсыз) · ← → пернелері · суретті үлкейту · таймер (уақыт біткенде автоматты аяқталады) · автосақтау + localStorage (бет жаңарса да, интернет өшсе де жауаптар жоғалмайды) · аяқтау алдында растау терезесі · нәтиже беті (дөңгелек диаграмма, бөлімдер бойынша progress bar, әр сұрақтың талдауы, сүзгі) · жеке кабинет.

**Мұғалім/әкімші:** Dashboard · курстар (мұқаба, баға, күйі) · жылдам енгізу (40 скринді бірден жүктеу + жауап кілті) · видео-талдау сілтемесі · нұсқаларды құру/өзгерту/өшіру · draft ↔ published (жариялау алдында 40 сұрақтың толықтығы тексеріледі) · 40 ұяшықтық редактор (тип нөмірге қарай автоматты) · drag-and-drop сурет жүктеу (JPG/PNG/WebP, 5 МБ, автоматты WebP-ке оңтайландыру) · жауап нұсқаларын қосу/өзгерту/өшіру/ретін ауыстыру · сұрақтың нөмірін бөлім ішінде ауыстыру · preview · нәтижелер (оқушы, нұсқа, күн, балл бойынша сүзу, сұрыптау) · оқушылар тізімі · платформа баптаулары.

## Кеңейту

- **Жаңа курс:** Админ-панель → Курстар → Жаңа курс (код өзгертпей). Курс беті `/courses/<slug>` автоматты жасалады.
- **Жеке видеосабақтар (нұсқасыз):** жаңа `lessons` кестесі және курс бетіне жаңа бөлім түрі — қолданыстағы auth, RLS үлгілері мен `VideoPlayer` компонентін қайта пайдалануға болады.
- **Басқа пәндер:** нұсқаның `subject` өрісі еркін; бағалау модулі пәнге тәуелсіз.
- **Төлем:** `profiles` немесе жеке `subscriptions` кестесі + `startAttempt()` ішінде қолжетімділікті тексеру.

## Production-ға шығару

Ең оңай жолы — [Vercel](https://vercel.com):

1. Репозиторийді Vercel-ге импорттаңыз.
2. **Environment Variables**: `.env.example` ішіндегі төрт айнымалыны қосыңыз (`NEXT_PUBLIC_SITE_URL` — нақты домен).
3. Supabase → Authentication → URL Configuration: Site URL мен Redirect URL-ге production доменін қосыңыз.
4. Deploy.

> Тестілеу: бағалау модулі мен валидацияға 54 unit тест жазылған (`npm test`). SQL migration мен RLS саясаттары PGlite (Postgres) ортасында тексерілген: оқушы сұрақтар мен дұрыс жауаптарды оқи алмайды, басқалардың нәтижесін көрмейді, аяқталған тесттегі жауапты өзгерте алмайды, рөлін көтере алмайды.
